# pgsql-cnpg

PostgreSQL HA on k3s via [CloudNativePG](https://cloudnative-pg.io) — the
official cloud-native operator for PostgreSQL.

## Architecture

- **Operator** (pinned release manifest, server-side apply) manages the whole
  lifecycle: bootstrap, replicas, automatic failover, rolling upgrades.
- **Cluster CR**: `instances: 3` (1 primary + 2 replicas by default), storage on
  `local-path`, resources sized by the profile.
- **Services**: `<name>-rw` (always the primary — app writes), `<name>-ro`
  (replicas — reads), `<name>-r` (any instance).
- **Backups**: native barman object store to S3 (`backup.barmanObjectStore`),
  WAL archiving + scheduled/base backups, retention policy, point-in-time
  recovery on restore.

## Configuration

| Env | Default | Description |
|---|---|---|
| `PG_K8S_NAMESPACE` | `pg` | Kubernetes namespace |
| `PG_K8S_NAME` | `pg` | Cluster name (services `<name>-rw`/`-ro`) |
| `PG_K8S_INSTANCES` | `3` | Instances (1 primary + N-1 replicas) |
| `PG_K8S_STORAGE_CLASS` | `local-path` | StorageClass for the data volumes |
| `S3_BUCKET` / `S3_ENDPOINT` | — | Enable backups when both are set (endpoint with or without scheme) |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | — | S3 credentials (never in the YAML) |
| `PG_S3_PREFIX` | `pg` | S3 key prefix (barman `destinationPath`) |

## Commands

```bash
bash validate.sh      # phase, ready instances, primary, psql PING via -rw
bash test/test.sh     # write/read, replication, failover, services
bash backup-s3.sh     # on-demand Backup CR + verify the S3 artifact
bash restore-s3.sh    # DR: bootstrap <name>-restore from the S3 store (PITR optional)
```

## Notes

- The app user password lives in the `<name>-app` secret (generated by the
  operator). Clients connect as `postgresql://app:<password>@<name>-rw.<ns>.svc:5432/app`.
- True same-name DR: delete the source cluster + PVCs first, then run
  `RESTORE_NAME=<name> restore-s3.sh`.
- The operator release is pinned via `PG_K8S_OPERATOR_MANIFEST`.
